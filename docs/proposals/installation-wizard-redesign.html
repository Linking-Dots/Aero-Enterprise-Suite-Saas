What I found in the codebase
Solid layout shell — InstallLayout.jsx
Step dots + progress bar already in place. Brand header consistent with auth pages. Theme toggle works. Good foundation.
Dual-mode routing — SaaS vs Standalone
Controller detects mode via class_exists(AeroPlatformServiceProvider). SaaS skips the License step. Route aliases for backward-compat included.
Config persistence via JSON file
storage/framework/installation_config.json — browser-refresh-safe state. Each step saves before Continue is enabled.
Processing polls /install/progress every 1.2 s
Retry + per-step status list. Works but risks polling loop on network failures. Needs exponential backoff.
4 UX pain-points identified
Step labels hidden on mobile, no in-flow inline validation, CSRF skipped globally, no estimated time on processing screen.
Redesign philosophy
Mobile-first step indicators
Current step labels use display:none on mobile. Redesign replaces with icon-only dots + a centered "Step X of N · Label" text line that's always visible at any width.
Inline field validation
Database & Settings forms currently show errors only on submit. Redesign adds debounced inline validation so the Continue button activates as fields pass — no silent failures.
Estimated time on Processing
Processing screen shows only a spinner and step list. Redesign adds an ETA line ("About 2 min remaining") based on observed step durations, reducing perceived wait anxiety.
Review step visual hierarchy
Review page is a flat mono table. Redesign groups config into collapsible sections (Database, Settings, Admin) with an edit shortcut on each section — no back-navigating to fix a typo.

High severity
High
CSRF disabled globally for all installation routes
Route::withoutMiddleware([VerifyCsrfToken::class]) wraps every route — including the production-side POST routes. This means all installation API endpoints accept cross-origin POST requests with no token check during the install window.
Fix: Scope the CSRF exclusion to only the 3–4 routes that legitimately need it (e.g., /install/progress, /install/check-requirements). Keep CSRF on all form-submit routes.
High
76 KB / 2054-line controller — no chunking
UnifiedInstallationController.php handles page rendering, AJAX validation, DB testing, config persistence, and execution orchestration in one file. Any change requires loading the full file; PHP opcache invalidates the entire unit on each touch.
Fix: Extract into thin action classes — ValidateLicenseAction, TestDatabaseAction, SaveSettingsAction, etc. — and keep the controller as a thin router. Matches the existing Steps/ pattern.
Medium severity
Med
Polling loop has no backoff or abort
Processing.jsx calls setTimeout(poll, 1200) on every iteration. A slow server or network hiccup causes the poll to fire before the previous response returns, potentially queuing multiple concurrent requests.
Fix: Implement exponential backoff (1.2s → 2.4s → 4.8s → cap at 10s) and abort the previous fetch on retry. Wrap with AbortController.
Med
Step label text hidden at all mobile widths
InstallLayout.jsx sets .il-step-lbl { display: none } and only shows it at min-width: 560px. On a 375px phone the user sees unlabeled dots with no text context of which step they're on.
Fix: Replace with a single centered "Step 3 of 9 · Database" text line below the dots. Always visible, zero extra width, better than tiny labels on a cramped row.
Med
Duplicate route definitions (legacy aliases re-register page routes)
installation.php defines e.g. GET / twice — once as installation.index and again as install.index. Laravel resolves both but the route cache will log a duplicate warning and named-route resolution is non-deterministic on the duplicate key.
Fix: Keep legacy names as ->name('install.index') aliases using Route::alias() or simply redirect old URLs to new route names in middleware.
Med
No inline validation — "Continue" enabled only after Save round-trip
Database and Settings forms disable Continue until a server round-trip succeeds. If the user corrects a typo they must re-click "Test" / "Save" even though the field is clearly changed. No client-side indication of why Continue is greyed out.
Fix: Add a useEffect debounce validator per field. Show inline field-level errors without a submit. Enable Continue only when all fields pass the client schema.
Low / cosmetic
Low
Processing step labels use raw class keys
Step keys like MigrationStep, PlanSeedingStep leak internal class names to users via the step list in Processing.jsx.
Fix: Map step keys to human labels in Processing.jsx: { MigrationStep: 'Running database migrations', PlanSeedingStep: 'Seeding subscription plans' }
Low
Complete step has no quick actions
After installation, the user lands on a congratulations screen with only a login button — no guidance on what to do next.
Fix: Add 3 contextual quick-action cards: Dashboard, Module configuration, Invite team members.
Low
AlreadyInstalled.jsx exists but isn't imported by any step
The file is in the Installation directory but the controller redirects to login rather than rendering the Inertia page, making the component unreachable.
Consider rendering it for informational purposes when someone hits /install post-installation, rather than a silent redirect.
All changes are confined to aero-ui (JSX/CSS) and aero-installation (PHP). No new npm dependencies required. Follows the same patterns as the registration flow and admin dashboard redesigns.
